# Registro de mudanças — 13/11/2026: login com usuário e senha

O Mojiki ganhou contas de usuário. Antes, a tela de boas-vindas só pedia um nome e todos os decks eram gravados com `user_id = 1`. Agora cada pessoa cria uma conta e só enxerga os próprios decks, cards e sessões de estudo. Requisito: [RF13](requisitos.md#rf13--login-com-usuário-e-senha). Caso de teste: [CT13](casos_de_teste.md#ct13--login-cadastro-e-recuperação-de-senha-rf13).

## 1. Como funciona para o usuário

- **Criar conta:** usuário, e-mail e senha (com confirmação). O e-mail só serve para recuperar a senha.
- **Regra da senha:** no mínimo 8 caracteres, com pelo menos um número e uma letra maiúscula. Enquanto a pessoa digita, uma lista embaixo do campo marca em verde cada regra cumprida.
- **Entrar:** usuário e senha. O usuário não diferencia maiúsculas ("Ana" = "ana").
- **Continua logado:** o token fica salvo no aparelho por 30 dias.
- **Esqueci minha senha:**
  1. digita o e-mail e recebe um código de 6 dígitos (vale 15 minutos);
  2. digita o código e a senha nova e já entra na conta.
- **Sair:** no menu de perfil (botão com a inicial). Apaga o token no servidor e no aparelho.

## 2. Backend

- **`auth.py` (novo):** hash da senha (PBKDF2-SHA256 com salt), geração de token e de código, regras de validação e envio do e-mail. Usa só a biblioteca padrão do Python, nenhum pacote novo.
- **Tabelas novas** (em `database.py`): `usuarios` (usuário e e-mail únicos, sem diferenciar maiúsculas) e `tokens`.
- **Rotas novas** em `main.py`:

| Rota | O que faz |
|---|---|
| `POST /auth/cadastro` | cria a conta e já devolve o token |
| `POST /auth/login` | confere usuário e senha e devolve o token |
| `GET /auth/eu` | dados do usuário do token |
| `POST /auth/sair` | apaga o token |
| `POST /auth/recuperar` | gera o código e manda por e-mail |
| `POST /auth/redefinir` | confere o código, troca a senha e devolve um token novo |

- **Rotas antigas protegidas:** todas as rotas de decks, flashcards, importação e sessões recebem `usuario_id = Depends(usuario_logado)`. Sem token válido, respondem **401**. O `user_id` que vinha no corpo da requisição passou a ser ignorado.
- **Dono dos dados:** um deck de outro usuário responde como inexistente (`{"erro": "Deck não encontrado"}`), seguindo a convenção que já existia.

## 3. Frontend

- **`screens/login_screen.dart` (novo):** substitui a antiga `welcome_screen.dart`. Um seletor no topo troca entre "Entrar" e "Criar conta".
- **`screens/recuperar_senha_screen.dart` (novo):** os dois passos da recuperação.
- **`services/auth_service.dart` (novo):** guarda token e usuário no SharedPreferences.
- **`api_service.dart`:** manda `Authorization: Bearer <token>` em toda chamada. Quando recebe 401, apaga o login e volta para `/login`. A constante `usuarioFixoId` foi removida.
- **`main.dart`:** guarda de rotas (`redirect` do go_router). Sem login, qualquer tela privada abre o login, inclusive digitando `#/home` na URL. O endereço antigo `/welcome` redireciona para `/login`.
- **`widgets/app_campo.dart`:** ganhou `obscureText`, `keyboardType`, `suffixIcon` (botão de mostrar a senha) e `autofillHints` (navegador e celular oferecem salvar a senha).

## 4. Envio do e-mail de recuperação

O backend manda o e-mail por SMTP quando estas variáveis de ambiente existem:

| Variável | Exemplo |
|---|---|
| `SMTP_HOST` | `smtp.gmail.com` |
| `SMTP_PORTA` | `587` (padrão) |
| `SMTP_USUARIO` | conta que envia |
| `SMTP_SENHA` | no Gmail, uma "senha de app" |
| `SMTP_REMETENTE` | opcional; padrão = `SMTP_USUARIO` |

Sem `SMTP_HOST`, o código **aparece no log do servidor** (terminal do uvicorn ou aba Logs do Render), o que serve para desenvolver e apresentar.

## 5. Segurança

- A senha nunca é guardada: só o hash PBKDF2 (200 mil iterações) com um salt diferente por usuário.
- O código de recuperação também é guardado só como hash. Depois de 5 tentativas erradas ele deixa de valer.
- Trocar a senha derruba os logins dos outros aparelhos.
- O login responde "Usuário ou senha incorretos" nos dois casos, e a recuperação responde a mesma mensagem exista ou não o e-mail, para não revelar quem tem conta.

## 6. Testes

- **Backend:** classe `TestLogin` em `test_backend.py`, com regras da senha, cadastro duplicado, token depois de sair, recuperação completa e decks separados por usuário. Os testes antigos passam o id do usuário de teste (`U`). Total: 29 testes.
- **Frontend:** `test/login_test.dart`, com as regras da senha, o cadastro que recusa senha fraca sem chamar o servidor e o login que salva o token e abre a Home. Total: 19 testes.

## 7. Limitações conhecidas

- **Banco local antigo:** decks criados antes desta mudança têm `user_id = 1` e passam a ser do **primeiro usuário cadastrado**.
- **Render:** o banco online é efêmero. A cada reinício, as contas somem e o app volta para a tela de login.
- **Render sem SMTP:** sem as variáveis acima, o código de recuperação só aparece nos logs do Render.
- **Progresso local:** sequência de dias e XP continuam guardados no aparelho (`progress_service.dart`), não por conta.
- **Sem limite de tentativas no login:** não há bloqueio depois de várias senhas erradas.
